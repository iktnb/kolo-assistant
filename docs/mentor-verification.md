## Практичне застосування спадкування

Реальний приклад — власний `KoloScreen` та його спадкоємці `FormScreen` і `HomeScreen`. Спільний метод повернення викликає перевизначений `leave()`: звичайний екран закривається, змінена форма захищає чернетку підтвердженням, головний екран запитує вихід. [Класи, методи й сценарій демонстрації](architecture.md#практичне-спадкування-й-поліморфізм).

Окремі приклади — `FieldError(InputError)` для спеціалізованої валідації та спадкоємці `argparse` для українських повідомлень. Штучну ієрархію моделей заради демонстрації не додано.

## Python-пакет і запуск із будь-якого каталогу

[Відтворювана інструкція](developer-guide.md#чисте-встановлення-python-пакета) збирає sdist/wheel, створює чисте середовище Python 3.12, установлює runtime-залежності й wheel без editable та виконує команди з `/tmp`. Перевіряються справжній імпорт із `site-packages`, entrypoint `kolo`, модульний запуск і упакований TCSS. PATH налаштовується для нового середовища, тому команда не залежить від поточного каталогу.

## Повторний прогін і виправлена затримка

Початкова перевірка публічного commit `d50b0c3`: чисте встановлення та 16 команд із двох сторонніх директорій пройшли. Повний новий прогін дав **224 PASS, 3 FAIL**, покриття **95.60%**. Три випадки стосувалися очікування збереження нотатки з повторюваним текстом майже на 10000 символів: diff займав 11.39 s без coverage та 37.16 s із ним і перевищував незмінений 30-секундний ліміт тесту.

У `BodyProjection.restore()` додано два еквівалентні швидкі шляхи: незмінений текст повертає оригінальні розділювачі одразу, а для початкового звичайного LF-тексту поточний канонічний текст уже є правильним результатом. Для зміненого історичного тексту з CRLF/CR/Unicode-розділювачами збережено попередній алгоритм `SequenceMatcher` і детерміноване зіставлення; його гірший випадок не усунуто.

[Нові регресійні перевірки](../tests/test_projection_performance.py) перевіряють точний текст і завершення максимального звичайного тексту за 5 s в окремому процесі, а також початкове зіставлення неоднозначних змішаних переносів. Новий тест відтворює затримку на початковому wheel. Таймаути, поріг coverage, попередні тести та формат даних не послаблювалися.

## Фінальний результат

Контролер виконав новий повний прогін локального коду: **232 PASS, 0 FAIL, 0 SKIP за 406.07 s**, **95.61%** усього `src/kolo` (1708 statements, 75 missing; поріг 80% незмінний). Це 227 попередніх і 5 нових регресійних випадків. Ruff format/lint, строгий mypy, Bandit, аудит усіх зафіксованих залежностей і wheel/sdist також пройдено.

Незалежний reviewer погодив зміну без зауважень: **18 додаткових цільових перевірок PASS**, **67081** порівняння з попередньою реконструкцією дали той самий точний текст. Це окремі перевірки огляду, вони не додаються до числа 232.

Після цього незалежний QA зібрав wheel із доопрацьованого коду й виконав окрему перевірку встановленого пакета:

Командні перевірки охопили contact/note CRUD, збереження між процесами, пошук, теги й сортування, дні народження, некоректні аргументи та валідацію без traceback і часткового запису. Повний набір також містить перевірки трьох розмірів TUI, чернеток, збоїв збереження й точних переносів рядків. Код і тести між оглядом та QA не змінювалися; статичні й security-перевірки повторно використано лише після побайтового звірення тих самих файлів і залежностей.

Початковий commit `d50b0c3` і попередній ZIP описують попередній стан. Для повторної здачі використовуйте доопрацьований код разом із цим звітом та оновлений архів. Ці результати підтверджують три технічні пункти відгуку; остаточне прийняття роботи залишається за ментором.
